## 2024-07-08 - [Pygame Video Rendering Optimization]
**Learning:** In a Pygame + OpenCV application, mapping OpenCV frames (ndarrays) to Pygame Surfaces using `np.transpose` and `pygame.surfarray.make_surface` is an expensive O(N) operation due to memory duplication and transposing. `pygame.image.frombuffer` offers a near zero-copy approach, but the input frame must be contiguous and the size tuple provided as `(width, height)`, overriding Numpy's `(height, width)` default. Moreover, Pygame 2.x doesn't support 'BGR' pixel formats directly, so `cv2.cvtColor` to RGB is still required. Finally, performing scaling natively via OpenCV's `cv2.resize` is significantly faster than Pygame's `pygame.transform.smoothscale`.
**Action:** Replace `pygame.surfarray.make_surface` with `pygame.image.frombuffer` passing `(width, height)` and ensure the array is contiguous when converting video frames to surfaces. Combine scaling into the OpenCV processing step before mapping to Pygame.
