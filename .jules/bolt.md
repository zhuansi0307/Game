## 2024-05-24 - Pygame Video Rendering Bottleneck
**Learning:** Pygame's `pygame.surfarray.make_surface()` combined with array transposing (`np.transpose`) is extremely slow for processing 1080p video frames from OpenCV (taking ~0.9s per 100 frames). However, `pygame.image.frombuffer(frame.data, size, 'RGB')` creates zero-copy surfaces and is nearly instantaneous (~0.001s per 100 frames). Also, while Pygame internally supports reading `BGR` with frombuffer in some setups, it can cause ValueErrors depending on the Pygame version and backend, so we must still convert `BGR` to `RGB` before creating the buffer surface for safety.
**Action:** When updating video frame parsing in Pygame, use `cv2.cvtColor` to convert to RGB, then use `pygame.image.frombuffer(rgb.data, size, 'RGB')` for zero-copy memory mapping instead of slow array manipulation.
