## 2024-05-30 - [Pygame Video Frame Rendering Optimization]
**Learning:** `pygame.surfarray.make_surface` + `np.transpose` is significantly slower than `pygame.image.frombuffer` when dealing with OpenCV frames in Pygame. For a 1080p frame, `surfarray` takes ~1.03s per 100 frames, whereas `frombuffer` takes ~0.017s per 100 frames (a ~60x speedup). This is because `frombuffer` can directly map memory if the array is contiguous and in the right format, whereas `surfarray` requires transposing the array structure (since Pygame expects `[x, y, c]` while OpenCV gives `[y, x, c]`) and then performs a memory copy. Also, Pygame 2.x `frombuffer` natively supports 'RGB' format string directly with `(width, height)` dimension tuples instead of needing transpose.
**Action:** When translating OpenCV frames to Pygame Surfaces, use `pygame.image.frombuffer(frame.data, (frame.shape[1], frame.shape[0]), 'RGB')` on a contiguous, RGB-converted numpy array instead of using `pygame.surfarray.make_surface` and `np.transpose`.
